# Pronunciada against ZIPA alone (ablation)

Generated by `python -m bench.eval_zipa_baseline`. Question: how much does Pronunciada add on top of the unmodified ZIPA phone recognizer, on the same held-out tests, items and statistics as results/SCOREBOARD.md?

## Baseline

- Model: `zipa-small-crctc-500k`, fp32, raw log-posteriors (`pronunciada.acoustic.AcousticModel`, no output adapter).
- Reference: the canonical phone sequence of Pronunciada's text front end for the prompt (`RefPhone.ipa`; the rule-based alternatives in `RefPhone.alts` are ignored), mapped to ZIPA token ids with `pronunciada.text.ipa.to_ids`.
- `gop` (primary): CTC Viterbi forced alignment of the canonical tokens (`pronunciada.lattice.build_lattice` with one zero-weight, non-skippable alternative per sound, `pronunciada.align.viterbi`; blank = logaddexp of `<blk>` and `▁`). Phone score = mean log-posterior of the canonical token over its aligned frames (blank frames excluded; floor −60); word = mean of its phones; sentence = mean of all phones.
- `match` (secondary): greedy CTC decode, unit-cost Levenshtein alignment with the canonical tokens. Phone = 1 if all of its tokens are matched, else 0; word = share of its phones matched; sentence = max(0, 1 − edit distance / canonical tokens) (1 − token error rate, insertions counted).
- Not used: adapter, lattice alternatives, native variants, calibrators, tone / stress / length / contrast heads, fitted thresholds, explain-away. Nothing was fitted, selected or thresholded on any data; the precision-at-recall rows set the baseline's threshold on the test set only to reach the recall that Pronunciada's shipped thresholds reach (the scoreboard's own protocol for Azure).

## How the baseline was checked for fitted components

- A fresh baseline worker process loaded only these Pronunciada modules: `pronunciada`, `pronunciada.acoustic`, `pronunciada.align`, `pronunciada.audio`, `pronunciada.lattice`, `pronunciada.text`, `pronunciada.text._eu_base`, `pronunciada.text._eu_common`, `pronunciada.text._eu_lts`, `pronunciada.text.base`, `pronunciada.text.en`, `pronunciada.text.ipa`, `pronunciada.types`. None of `pronunciada.adapter`, `calibrate`, `variants`, `scorer`, `prosody`, `features`, `contrast_heads`, `length`, `sound_emb`, `delivery`, `coach` was imported; the scoring run's workers loaded 23 modules: the same set plus the other nine languages' front ends (`pronunciada.text.<lang>`, `_cjk_common`).
- Its log-posteriors on 20 speechocean762 test clips differ from the raw-model posterior cache (`bench/postcache.py`, stored as float16) by at most 0.016 (float16 rounding); applying the English adapter would change them by up to 26.2 (largest |Δ| over frames and tokens, in low-probability columns) and the GOP phone scores by 0.251 on average, so the adapter is demonstrably not in the path.
- The alignment lattice has a single alternative per sound (alt indices [0]), all arc weights 0 and no skip arcs; every phone list equals the `phones` field of Pronunciada's cached outputs for the same prompt (asserted for speechocean762, L2-ARCTIC and EpaDB).

## Data and Pronunciada values

Baseline scored 14454 records over 11304 audio files, 17.15 h of audio (speechocean762, L2-ARCTIC, EpaDB test; fleurs-swap test, 10 languages; OMPAL test; cv-real test half). Pronunciada's values are recomputed from the cached per-utterance outputs the scoreboard scripts read (`calib/api/*.pkl`, the OMPAL and cv-real output caches); 60 of 60 recomputed values equal the value in results/tables/*.json to 3 decimals.

## Notes per test

- speechocean762: items, phone/word fallbacks and exclusions as `bench/eval_english.py` (Pronunciada = `ours_B` 0–2 phone score, word-accuracy regression, sentence heads). The baseline has one sentence score, correlated with each expert sentence score.
- L2-ARCTIC / EpaDB: annotation phones as `bench/eval_english.py err_items`; error score = −gop (match: 1 − match); unaligned annotation phones take the mean of the neighbouring aligned phones.
- Coaching: the phones of `bench/coach/azure_yardstick.py` (expert-scored, aligned to ours and to Azure); flag score = −gop, thresholded at the recall Pronunciada's shipped thresholds reach (ties included, `prec_at_recall`); the `match` scores are binary, so its reached recall can be higher: precision at 'careful' recall: 0.537, precision at 'balanced' recall: 0.537, precision at 'eager' recall: 0.537.
- OMPAL: units, labels and speaker bootstrap of `bench/eval_ompal.py`; unit score = min over overlapping baseline words (exp of the word GOP, so an uncovered unit's 0 stays the lowest score).
- Swap benchmark: the scoreboard's record set (clusters both Pronunciada and Azure scored), `bench.eval_swap._metrics`, 1000 utterance resamples, seed 0.
- cv-real: `bench/eval_cv.py` speaker bootstrap (2000, seed 0) on the clips both Pronunciada and Azure scored; baseline score = the sentence score.
- Items the baseline could not score: the text front end produced a reference for every record (0 front-end failures). 9 cv-real clips (zh-CN/A: 3, ja/A: 6) are too short for their canonical token sequence, so the forced alignment does not exist; by the rule fixed in advance every phone gets the floor −60 (the lowest possible gop score; match is computed normally). Every other test item was scored normally; no item was dropped beyond the scoreboard's own exclusions.
