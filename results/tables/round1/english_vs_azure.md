# English: pronkit vs Azure Pronunciation Assessment

All pronkit numbers come from the public API (`pronkit.Scorer("en").score(audio_path, text)`, fp32, default strictness 0.5) run on the held-out TEST splits; Azure numbers from its cached responses on the same clips (en-US, `bench/azure_pa.py`). Generated by `python -m bench.eval_english`. CIs: 95 % speaker-clustered bootstrap (1000 resamples); Δ = ours − Azure with a paired speaker bootstrap, p = two-sided bootstrap p-value.

Shipped English sound model: **B** (English-specific, feature set B: evidence + phone identity; it beat the universal model A on speaker-grouped CV of speechocean762 train). A = universal evidence-only model (what every other language uses), C = B + utterance duration / speaking rate (benchmark transparency only, never shipped). Word and sentence calibrators are universal (no word identity) and consume the universal sound model's outputs.

## 2. Calibration on speechocean762 TEST

ECE = expected calibration error with 15 equal-mass bins; Brier; AUC of P vs the binary truth. Truths: lenient = human score ≥ the lenient threshold, strict = ≥ the strict threshold (phone 1.0 / 1.8 on 0–2; word 5 / 8 on 0–10; sentence accuracy 6 / 8 on 0–10). The s = 0.5 blend is compared with the **midpoint** truth: human score ≥ (lenient + strict) / 2 = phone ≥ 1.4, word ≥ 6.5 (i.e. ≥ 7, integer scores), sentence accuracy ≥ 7. Phone level: our phones aligned to a human-scored phone (shipped English model; the universal model U below). Word level: our words aligned to a human-rated word, P = the lowest of the aligned words. Sentence: every utterance.

## 3. Real learner errors: l2arctic TEST and epadb TEST

Items = the annotators' canonical phones (insertions and unparsed labels excluded); error = substituted or deleted. Ours: score = 1 − P at strictness 0.5; unaligned annotation phones take the mean of the neighbouring aligned phones. Azure: score = 100 − phoneme AccuracyScore, aligned to the annotation's canonical phones with the speechocean762 alignment (per word for l2arctic, over the utterance for epadb, which has no word grouping); unaligned phones take the word (l2arctic) / utterance-mean (epadb) accuracy. "F1 @ train thr" uses the best-F1 threshold of the same model on the corpus' TRAIN split (no Azure responses exist for the train splits, so Azure has none). Models: U = shipped universal, A = universal on speechocean762 only, B = shipped English, C = B + duration/rate, W = universal on the wide mix (so762 + l2arctic + epadb + FLEURS synthetic), R = so762 + l2arctic + epadb. W and R contain the l2arctic / epadb TRAIN splits; no model saw a test speaker.
