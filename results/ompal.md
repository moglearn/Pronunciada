# OMPAL: French-speaking learners of Taiwan Mandarin, Pronunciada vs Azure

Generated by `python -m bench.eval_ompal --steps ours,report` (tone model **tone_zh_v2**, onnx sha1 98c068d8, pronunciada fingerprint 4fb94ea04d9a6958). Azure: zh-TW, zh-CN; **zh-TW is the pre-declared primary**, zh-CN is a sensitivity check.

## How to read this

This is the first expert-marked learner benchmark outside English for this project. It is small and narrow: one first language (French), 18 test learners (first- and second-year students; the shipped test files contain 18 distinct learners, not 20), and Taiwan Mandarin read from Traditional-script prompts, marked by Taiwanese teachers — so Taiwan norms (e.g. less retroflexion, fewer neutral tones, different readings of some characters) are the reference, while Pronunciada's pronunciations come from a Mainland-oriented G2P and its tone model was trained on Mainland and Taiwan native speech. Speaker-level confidence intervals are wide because there are only 21 test speakers (18 learners); the utterance-level column is narrower but treats one speaker's utterances as independent, which they are not. Nothing in Pronunciada has ever seen this data, and nothing was tuned on DEV or TEST. The metric definitions below were fixed before any system output on OMPAL was computed. Word units are single characters but both systems score whole words: a two-character word gets one score for both characters, for both systems.

## Pre-specified metrics (fixed 2026-11-16, before any result was seen)

- Units: OMPAL word units = one Hanzi each; labels = the shipped majority of three raters; "correct" = tone, consonant and vowel all marked correct.
- Unit score = lowest score over the system's words overlapping the unit (character spans, as in `bench/eval_swap.py`). Ours: `word.prob` at default strictness; diagnostic channels: lowest syllable `tone_prob` inside the unit, lowest `word.sounds_prob`. Azure: word `AccuracyScore` (Omission = 0).
- A unit no system word covers, and every unit of an utterance the system failed on, gets that system's lowest score (0); nothing is dropped for a system failure.
- Word level, TEST all speakers (natives included): primary AUC any-error vs correct; (a) tone-only error vs correct; (b) consonant-or-vowel error vs correct; learners-only as a secondary table; hit rate at 5 % / 10 % false alarms with the threshold set on the correct units of the natives and, separately, of the learners (positives = learners' units).
- Sentence level, TEST learners (natives are all 5/5/5, so they are a secondary row): Pearson and Spearman with the mean teacher score — accuracy (ours `accuracy` / Azure AccuracyScore), fluency (ours `fluency` / Azure FluencyScore), prosody (ours `prosodic` / Azure PronScore, the nearest available: Azure has no Mandarin prosody score); secondary: ours sentence `prob` / Azure PronScore vs teacher accuracy.
- 95 % percentile bootstrap, 2000 resamples, over speakers and over utterances; Δ = ours − Azure on the same resamples, two-sided paired-bootstrap p.

- Split (by speaker, fixed before scoring): TEST = speakers of the shipped `test/test_[1-5]_scores.json` (18 learners + natives SPEAKER01001/01002) plus native SPEAKER01003, which no shipped split uses; DEV = the other 28 learners. No speaker is in both. The shipped test files do not match the speaker lists printed in the corpus README; the files were used. Manifest: `results/tables/ompal_manifest.json`.
- Units: one character each; 9 learner units list two characters where the speaker inserted or swapped a word (e.g. 還也 against the prompt's 還): the unit keeps the prompt character it matches. Dropped: 4 TEST units whose character is not in the prompt (a native recording annotated with four extra characters) and the word level of 1 TEST utterance (00100218, whose unit list interleaves two sentences); its sentence scores are kept. One learner prompt (00204117) has four trailing characters with no units; they are simply not evaluated.
